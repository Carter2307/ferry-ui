## Design rules

- **The menu changes the section in place.** The items of `InnerMenu` have no `href`. `value` and `onValueChange` hold the current section. On a phone, the menu is a row of tabs.
- **One form for the page.** The cards have `asDiv` because the page holds the only `<form>`.
- **One save bar for all the sections of the form.** The sticky `SaveBar` gets `dirty`, `invalid` and `saving`. Its "Save changes" button is the submit button of the form.
- **A checkbox for a value that the form saves.** A [Switch](/docs/components/switch) is for a setting that applies immediately.
- **A hook holds the headers.** `useKeyValueRows` gives the rows and the errors to `KeyValueEditor`. It gives the dirty state to the save bar.
- **The danger zone is not in the form.** Each `ActionRow` opens a `ConfirmDialog`. To delete the workspace, the user must type its slug.

## Sections

The `defaultSection` prop of the example sets the first section.

| `defaultSection` | The section shows |
| --- | --- |
| `general` | Rows with an input, a textarea, a select and radio cards. This is the default. |
| `notifications` | One checkbox for each row. |
| `billing` | Stacked fields in a grid of two columns. |
| `webhooks` | A URL field and the editor of the request headers. |
| `danger` | Two actions, each with a confirmation. |
